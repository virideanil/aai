# Writing as continuing work

nano'ai's writing workflow exercises the same language core, sources, catalogue,
work journal, exact computation and artifact recovery used by other tasks. Its
first purpose is to expose what the current system can actually plan, write,
criticize and revise. The unchanged original-BF16 model is the control. Parameter
learning and literary quality have separate evidence.

## A complete episode

The brief declares the intended form, language, audience, required details and
scope. Source records distinguish fictional canon, empirical evidence and
critique. A fictional invention can extend a story; it cannot silently revise a
protected fact or become evidence about the real world. The model proposes a
plan and writes editable sections. An attributed critique can lead to a revised
section. The original draft and its costs remain available.

An installment binds the task revision, core and representation versions, exact
inputs, producing operation, source dependencies and observed output. Generated
text enters the source catalogue with its own role and byte barcodes. A source
change invalidates affected derived work. A fresh process reconstructs current
work from the same journal and reads completed artifacts before generating again.
Recovery never repeats a confirmed publication merely to restore a status flag.
The public writing command performs this check before starting a model worker.

Authoring and writing share one selected working-context projection. Continuing
identity, current observed calculations and explicitly selected scratchboard units
enter the actual writing prompt with their scope, review and dependencies. Partial
previews remain partial, and unresolved ranges supply no invented text. A selected
revision or correction invalidates dependent output; an unrelated unit leaves it
reusable. Frozen teaching comparisons keep their original prompts and require a
new protocol before adopting changed inputs.

Authoring, writing and authored teaching also use the same versioned input
envelope. Phase-specific output requirements and selected lessons or criticism
activate their relevant rules. Generated-experience checks read the envelope's
task and source fields so literal quotes and newlines retain their exact meaning.
Evaluator answers and task-split labels stay outside the model input.

This shared record and input path does not yet carry numerical model state from
one writing phase into the next. The current native worker rebuilds that state.
The native model's ordinary chat template removes previous reasoning at a new
user turn, which prevents blindly appending a phase to the old cache. A continuing
state consumer needs a qualified task-segment format, compatible full-state
checkpoints, source-correction replay and fresh-process verification.
If a phase boundary adopts reasoning-free canonical history, its numerical state
must be computed from that canonical sequence. Include the replay cost; the
post-generation cache still reflects every reasoning token it processed.

The bounded first trial uses an original story brief and prescribed plan, draft,
critique, revision and continuation phases. A Turkish correction changes an
English story constraint. A quantity task checks the role of exact computation.
The trial includes a fresh-process recovery and a comparison with a direct
unchanged-model response. This tests an integrated working path. It does not
establish an autonomous editor policy, a learned memory improvement or a complete
book-length capability.

## Knowledge and education

Language supplies expression and contextual distinctions. Mathematics supplies
composition, formal implications and exact checks under stated assumptions.
Observation, sources and experiments supply evidence about the world. Craft
requires varied examples, criticism and revisions judged as complete work.
These strands develop together; none of them makes unavailable facts known.

Learning records retain errors, useful feedback, context, actual consequences
and unresolved judgments. A generated line is observed behavior. Its existence
does not make it correct or eligible as a training target. Independent checked
corrections can provide supervision; approved examples retain their source and
scope. Candidate weights, factual memory, working state and editable manuscripts
have different update rules. The tokenizer remains frozen within a run. When an explicitly declared training/replay experience supplies a correction, preparation uses its recorded prompt. Ordinary writing stays outside weight updates until its split, corrective target and evaluation have been qualified.

The next learned candidate must beat its parent on unseen complete tasks while
retaining general language, source use, conduct and recovery. The existing
one-update BF16 feasibility result and the later host-swap stop govern resource
admission. The writing baseline itself changes no model weights.

## What the assessments mean

| Question | Evidence |
|---|---|
| Was the work executed and recovered? | Journal dependencies, exact artifact readback, once-only recovery and current source revisions |
| Did it follow the brief? | Explicit facts, protected names, quantities, corrections and completed requested sections |
| Is the story coherent? | Character knowledge, timeline, causal continuity and consequences assessed across the complete manuscript |
| Is the writing good? | Attributed reader comparison of voice, specificity, imagery, character and revision quality |
| Did learning help? | Unchanged, in-context and adapted controls on unseen tasks with retention and full-cost measurements |

The same model's critique is useful feedback with correlated blind spots. It is
not an independent quality verdict. Mechanical checks report their exact scope.
Presence of a name, lower loss, rhyme, vocabulary variety and file size cannot
stand for literary merit. Failed checks remain visible and prevent a task-success
claim; an incomplete generation stays an incomplete attempt.

## The proposed literary corpus

Fable proposed Shakespeare and Oscar Wilde as future stylistic study material.
Source and edition identity, acquisition authority, rights, cleanup and exact
bytes must be recorded before use. Whole works, including their revisions and
near-duplicates, stay within one split. Keep training, validation and frozen
confirmation distinct. Prompts and selection decisions exclude confirmation
material. A pretrained model may already know these works, which limits any
claim of unseen-text generalization.

The source manifest belongs in `evals/literary/source-manifest.json` when actual
sources are selected. Raw books belong outside Git in `.local/literary`; private
generation and learning receipts stay at the experiment owner. The original
story trial requires no new corpus acquisition.

Measure quality as a function of data seen and complete elapsed cost, including
preparation, training, inference, assessment and failed attempts. In-context
imitation is one comparator. Reader judgments remain visible alongside linguistic
diagnostics. There is no supported deadline for reaching a named author's quality.

## Execution boundaries

C++ runs the exact tokenizer and native model kernels. Python coordinates the
existing state and artifact APIs. This boundary keeps repeated computation native
and makes the complete working process inspectable. Porting orchestration earns
its cost only after a real bottleneck is measured. The first trial uses local
files, the admitted BF16 source and existing host guards. It grants no network,
GUI or publication effect.
